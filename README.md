# Apply Local — 한국 채용 지원서 자동 입력 Agent

Apply Local은 PDF 이력서를 읽어 한국 채용 사이트의 지원서 양식에 개인정보와 학력을 자동으로 입력하는 **로컬 우선(local-first) 데스크톱 Agent**입니다.

로그인, CAPTCHA, 본인 인증, 약관 동의, 최종 제출처럼 사람이 결정해야 하는 단계는 사용자에게 맡기고, 반복적인 입력 작업만 자동화합니다. 이력서와 개인정보는 사용자 컴퓨터 밖으로 보내지 않습니다. AI는 이 컴퓨터에서 실행되는 Ollama 모델만 사용합니다.

## 주요 기능

### 이력서 이해
- 텍스트형 PDF에서 다음 항목을 추출합니다.
  - 이름(한글·영문), 생년월일, 연락처, 이메일·보조 이메일, 주소
  - 병역·장애·보훈 여부
  - 대학교·대학원 학력
- 표 형식이 아닌 이력서는 로컬 LLM(Ollama)이 보조로 추출합니다. 이때 **이력서 원문에 실제로 있는 값만** 받아들입니다.
- 영문 이름은 한글 성을 기준으로 성과 이름의 순서를 판단합니다(`ZHANG YAN` → 성 ZHANG / 이름 YAN).
- 추출 결과는 미리보기 표에서 확인하고 고칠 수 있습니다.

### 지원서 이해
- 실제 브라우저 DOM에서 입력 필드, 라벨, 영역, 선택지, 컨트롤 종류를 찾습니다.
- 사이트 구현이 제각각이어도 읽을 수 있도록 다음을 처리합니다.
  - 잘못 연결된 `aria-labelledby`
  - 바깥 블록 텍스트로 쓴 질문
  - `div.form-label` 형태의 캡션
  - 0×0으로 숨기고 라벨만 버튼처럼 보이게 만든 라디오
- 속성 이름(`educationalBackground.universities.0.schoolName`)과 라벨 규칙으로 각 필드가 이력서의 어떤 항목인지 판단합니다.
  - `성`/`이름` 분리 필드, 세 칸 휴대폰, `(영문 이름) Gildong` 같은 예시가 붙은 라벨도 처리합니다.
  - 비상연락처·보호자·추천인 등 **지원자 본인이 아닌 사람**의 필드에는 입력하지 않습니다.
  - 희망 연봉, 입사 가능일, 지원 경로처럼 **이번 지원에 대한 본인의 선택**은 자동으로 채우지 않습니다.

### 입력과 검증
- **형식 변환**: 전화번호, 날짜, 평점을 사이트의 placeholder·pattern·maxlength에 맞춥니다.
- **선택지 변환**: 한국어 이력서 값을 영어 선택지로 바꿉니다.
  - 재학 → `Enrolled`
  - 비대상 → `Not applicable`
  - 최종 학력 → `Postgraduate school (master's)`
- **지원 컨트롤**: text, select, radio(숨김형 포함), ARIA radio, 자동완성, 사용자 정의 선택, 연/월/일 select, 달력 위젯.
- **입력 후 검증**: 입력한 값을 브라우저에서 다시 읽어 확인합니다. 실패하면 대체 형식으로 한 번만 재시도하고, 그래도 실패하면 값을 지운 뒤 사용자에게 알립니다.
- **주소 검색 창 자동 처리**:
  1. 읽기 전용 주소 칸 옆의 「우편번호 찾기」를 누릅니다.
  2. Kakao 우편번호 창에서 이력서 주소로 검색합니다.
  3. 결과가 하나일 때만 선택하고, 기본주소·우편번호를 확인한 뒤 상세주소를 입력합니다.
  4. 결과가 여러 개면 검색해 둔 창을 열어 두고 사용자가 고르게 합니다.
- **입력 블록 추가**: 「대학/대학원 학력 정보 추가」 버튼을 눌러 입력 블록을 열고 채웁니다. 최종 학력은 이력서 학력에서 계산합니다.
- **민감 항목**: 병역·장애·보훈은 이력서 값대로 입력하되, 항상 「입력됨 · 확인 필요」로 표시합니다.

### 모든 필드에 결과를 남기는 표와 2차 확인
- 검출된 모든 필드는 결과 표에 한 줄씩 나타납니다. 조용히 사라지는 항목이 없습니다.
- 각 줄의 상태는 다음 중 하나입니다.
  - 입력·검증 완료
  - 기존 값 유지
  - 입력됨 · 확인 필요
  - 이력서에 없음
  - 직접 처리
  - 입력 불가(비활성)
- 규칙으로 채우지 못한 항목은 로컬 LLM이 이력서 원문에서 근거 문장을 찾아 한 번 더 확인합니다.
  - **근거 문장이 원문에 그대로 있을 때만** 입력합니다.
  - 값의 종류도 검사합니다. 예를 들어 이메일 형식의 값은 이메일 칸에만 넣습니다.
- 「상세」 버튼으로 이유를 보고 선택지 중에서 고르거나 직접 값을 넣을 수 있습니다.

## 안전 원칙

- 아이디·비밀번호를 입력하지 않고, CAPTCHA·MFA를 처리하거나 우회하지 않습니다.
- **최종 제출·저장 버튼은 절대 자동으로 누르지 않습니다.**
  - 자동으로 누르는 버튼은 명시적인 `type=button`의 「다음」, 주소 검색, 학력 「추가」뿐입니다.
- 페이지에 이미 입력된 값은 덮어쓰지 않습니다.
- 약관 동의 체크박스, 자기소개서 같은 서술형 문항, 첨부파일은 자동으로 처리하지 않습니다.
- 도메인 정책
  - HTTPS 페이지만 엽니다.
  - 다른 도메인으로 이동하거나 다른 도메인의 iframe을 쓰려면 사용자 승인을 받습니다.
  - 예외: Kakao/Daum 우편번호 검색 도메인 2개는 사용자 결정에 따라 기본 허용합니다. 이 도메인에는 이력서 주소만 입력합니다.
- 웹페이지의 문구를 Agent에 대한 지시로 해석하지 않습니다.
- 개인정보 보관
  - 이력서 원문과 개인정보는 프로세스 메모리에만 둡니다. 작업을 취소하거나 프로그램을 종료하면 지웁니다.
  - SQLite에는 작업 상태 메타데이터만 저장합니다.
- 로컬 LLM은 루프백 주소(127.0.0.1)의 Ollama만 허용합니다. 프롬프트와 응답은 로그나 파일로 남기지 않습니다.

## 동작 흐름

```text
PDF 이력서 ─▶ 규칙 파서 (+ 로컬 LLM 보조, 원문 근거 검사) ─▶ ResumeProfile (메모리)
                                                    │
채용 페이지 ─▶ Form Inspector ─▶ 필드 목록 + 「추가」 블록 펼치기
                                                    ▼
                     Mapper (속성 의미 + 라벨 규칙 + 구조 판단)
                                                    ▼
                     Planner ─▶ Formatter / Widget Adapter (주소 검색 포함)
                                                    ▼
                     Executor (Playwright) ─▶ Readback Validator
                                                    ▼
                     필드 장부(모든 필드 1줄) ─▶ 로컬 LLM 2차 확인(근거 문장 필수)
                                                    ▼
                     사용자 검토(「상세」) ─▶ 최종 제출은 사용자가 직접
```

화면은 PySide6 네이티브 창입니다. 내부적으로는 `127.0.0.1`의 임의 포트와 실행마다 새로 만드는 토큰을 쓰는 로컬 FastAPI 프로세스를 통해 핵심 모듈을 호출합니다. 브라우저는 작업마다 새로 만드는 Chromium 프로필이며, 평소 쓰는 Chrome과는 분리되어 있습니다. 이 프로필은 작업이 끝나면 삭제됩니다.

## 설치

Python 3.11 이상이 필요합니다.

```bash
python3.11 -m venv .venv
.venv/bin/pip install -e .
.venv/bin/python -m playwright install chromium
```

로컬 LLM 보조 기능을 쓰려면 Ollama를 설치하고 모델을 받습니다. Ollama가 없어도 규칙 기반 기능은 그대로 동작합니다.

```bash
brew install ollama && brew services start ollama
ollama pull qwen2.5:7b
```

## 실행

```bash
.venv/bin/python run_local.py
```

1. PDF 이력서를 `선택`하고 채용 지원 페이지 URL을 입력한 뒤 `이력서 읽고 준비`를 누릅니다. 미리보기 표에서 추출 값을 확인합니다.
2. `브라우저 열기`를 누르고, 열린 브라우저에서 로그인·본인 인증을 직접 완료해 지원서 화면으로 이동합니다.
3. `이 페이지 자동 입력`을 누릅니다.
   - 규칙 입력이 끝나면 결과 표가 먼저 나타납니다.
   - 이어서 로컬 LLM 2차 확인이 자동으로 진행되며, 1~3분이 걸립니다.
4. 「확인 필요」 항목은 「상세」에서 고르거나 고칩니다.
5. 입력 결과를 직접 검토한 뒤 **저장·최종 제출은 사용자가 직접** 합니다.

  - 숨김 라디오

## Before / After 평가

`evaluation/` 폴더에는 규칙 기반 Before 버전과 개선된 After 버전을 같은 조건에서 비교하는 도구가 있습니다. 결과 파일에는 이력서 값이나 URL을 저장하지 않으며, 사이트는 익명 별칭으로만 기록합니다.

| 스크립트 | 역할 |
|---|---|
| `check_resume.py` | PDF에 추출 가능한 텍스트가 있는지, 항목별 값 존재 여부만 확인 |
| `record_run.py` | 실제 사이트에서 검사·입력 결과와 소요 시간 기록, `--dump-structure`로 값 없는 필드 구조 스냅샷 저장 |
| `score_runs.py` | 정답 라벨(`evaluation/labels/*.csv`)과 비교해 지표 계산 |

주요 지표: 필드 매핑 정확도, 자동 입력 성공률, 검증 통과율, 잘못된 입력(Unsafe fill), 설명 없이 누락된 필드 수, 사용자 개입률, 재시도 횟수, 지연 시간.

```bash
.venv/bin/python evaluation/check_resume.py /path/to/resume.pdf
.venv/bin/python evaluation/record_run.py --variant after --site site-a --resume /path/to/resume.pdf --url "https://..."
.venv/bin/python evaluation/score_runs.py
```

## 한계

실제 사이트(GreetingHR 기반 채용 페이지, SK Careers) 테스트에서 확인했거나, 아직 구현하지 않은 내용입니다.

### 입력이 안 되거나 사용자 확인이 필요한 경우
- **검색 후 선택하는 입력칸**
  - 학교명처럼 글자를 입력하면 목록이 뜨고, 그중 하나를 골라야 하는 칸이 있습니다(예: SK 대학원 학교명).
  - `role=combobox`를 표시하지 않은 사이트 자체 위젯은 필드로 인식되지 않아 결과 표에도 나타나지 않습니다.
- **한글 값 → 영문 선택지 변환이 일부만 됨**
  - 재학 상태, 병역·장애, 최종 학력은 변환됩니다.
  - 학교 소재지(서울 → `Seoul`) 같은 지역명 변환표는 아직 없어, 사용자가 「상세」에서 골라야 했습니다.
- **반복 입력 블록**
  - 「추가」 버튼은 대학·대학원 학력만 지원합니다.
  - 경력, 자격증, 어학, 수상 같은 반복 블록은 아직 지원하지 않습니다. 이력서 구조에도 아직 목록으로 들어 있지 않습니다.
- **블록 안의 예/아니요 선택**
  - 편입·복수전공·부전공 여부, 전공 계열, 학점 기준은 사용자 판단으로 남깁니다.
- **학위**
  - 이력서에 석사/박사가 적혀 있지 않으면 최종 학력의 학위를 추측하지 않습니다.
- **주소 검색**
  - Kakao/Daum 우편번호 창만 지원합니다. juso.go.kr 등 다른 검색 창은 사용자가 직접 처리합니다.
  - 검색 결과가 여러 개면 사용자가 고릅니다.
- **라벨 인식 실패**
  - 라벨이 독특한 사이트에서는 내부 name(`appJobRoleLevel1` 등)이 항목 이름으로 보이고, 규칙이 그 필드를 연결하지 못할 수 있습니다.
  - 로컬 LLM이 메타데이터만 보고 필드를 분류하는 분류기는 아직 구현하지 않았습니다.
- **스캔(이미지형) PDF**
  - 지원하지 않습니다. OCR이 필요합니다.
- **영문 `First name / Last name`**
  - "영문" 표시 없이 영어 라벨만 있으면 페이지 언어를 판단하지 않고 한글 이름 성분으로 연결합니다.

### 범위 밖이거나 아직 하지 않은 흐름
- **여러 페이지 지원서**
  - 다음 페이지로 가기 전에 「저장」을 눌러야 하는 지원서(예: 삼성)는 아직 지원하지 않습니다.
  - 계획: 페이지마다 사용자에게 저장 여부를 확인받은 뒤 진행합니다.
- **자동 입력하지 않는 항목**
  - 자기소개서·서술형 문항, 첨부파일, 약관 동의, 희망 연봉·입사 가능일 같은 본인 선택 항목은 의도적으로 자동 입력하지 않습니다.
- **여러 URL 순차 처리, 이력서 로컬 저장**
  - 아직 지원하지 않습니다. 매번 이력서를 다시 분석합니다.
- **임시 저장 가능성**
  - 일부 사이트는 사용자가 제출하지 않아도 입력 내용을 임시 저장할 수 있습니다.

### 성능과 사용성
- **로컬 LLM 2차 확인 속도**
  - 7B 모델로 1~3분 걸립니다. 진행 중에는 버튼이 비활성화되고, 단계별 진행률 표시는 아직 없습니다.
- **화면**
  - 창이 크고, 결과 표에 내부 경로(`education.university.major` 등)가 함께 보입니다.
  - 작은 팝업형 창과 한국어 항목명만 보이는 표로 바꾸는 개편이 예정되어 있습니다.
- **최종 제출 안내**
  - 모달 창으로 한 번 표시됩니다.

### 평가
- **실사이트 평가 범위**
  - 실제 사이트 검증은 2곳에서만 했습니다. 정량 Before/After 데이터셋은 아직 작습니다.
- **오프라인 평가셋**
  - 사이트 구조 스냅샷에 정답을 붙여 매핑 정확도를 오프라인으로 비교하는 평가셋(규칙만 vs 규칙 + 분류기)은 다음 단계입니다.

### 보안상 고려할 점
- **브라우저 제어 권한**
  - 작업용 Chromium은 Playwright가 DevTools Protocol로 완전히 제어합니다. 기술적으로는 쿠키 접근도 가능하며, 앱이 쿠키나 비밀번호를 읽지 않는 것은 코드 설계에 의한 것입니다.
  - 제어 통로는 파이프라서 외부 포트를 열지 않습니다. 로컬 API는 루프백 주소와 토큰으로 보호합니다.
- **같은 사용자 계정의 다른 프로그램**
  - 작업이 진행되는 동안 브라우저 프로필 폴더에 로그인 세션 쿠키가 남아 있습니다.
  - 같은 OS 사용자 계정에서 실행 중인 악성 프로그램은 이 폴더에 접근할 수 있습니다. 일반 Chrome과 같은 위험입니다.
- **추가 예정 보완**
  - 창을 닫으면 즉시 프로필 삭제
  - Chromium 비밀번호 저장 기능 끄기
  - 허용된 도메인 목록 상시 표시
